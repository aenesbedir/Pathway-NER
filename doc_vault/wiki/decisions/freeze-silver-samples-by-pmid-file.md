# Freeze silver samples as PMID files

**Decision.** Sample selection is either **frozen or sampled, never both**. Every
silver run writes its effective sample to `<output stem>_pmids.txt`, and
`--pmids FILE` re-runs exactly that list with no sampling.

**Why.** `select_sample()` was not stable across vocabulary changes: widening the
golden PMID exclusion from 5 to 10 re-proportioned every disease category and
re-walked the shared RNG, shifting the 1k draw by **49% at the same seed=42**.
The pilot the doccano batches were built from could no longer be regenerated by
running the script — a model swap would have re-labelled a *different* thousand
abstracts than the annotators are reviewing.

**Verified.** `data/silver/pilot_1k_pmids.txt` reproduces `pilot_1k.jsonl`
byte-for-byte from cache with 0 LLM calls.

**The principle.** *Reproducibility is frozen artefacts, not determinism.* Ollama
is not deterministic even at `temperature=0, seed=42` — re-querying 91 abstracts
changed 4 of them. Everything else in the pipeline is pure, so the single
stochastic step is pinned by the cache and the sample by the PMID file.

Golden PMIDs are dropped from `--pmids` input too, not only from sampling: an
explicit list is the one path that skips the sampler, and evaluation data must
never reach silver by either route.
